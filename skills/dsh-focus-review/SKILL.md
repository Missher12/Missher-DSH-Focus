# 先核对需求，再检查成果

在当前会话完成检查，不自动创建子代理，不声称自己做了独立审查。

1. 对照最新用户要求与实际成果，检查必要内容是否齐全、限制是否遵守、是否出现无关扩展。已有材料足够就直接使用，不为检查重复收集或建立额外文档。
2. 只选择当前任务相关的核对方式：
   - 调研和建议：结论是否由所引来源支持，来源是否适用于当前问题和时间；区分事实、推测、缺失及矛盾。足够支持结论后停止检索。
   - 文稿和文件：内容、格式、读者和交付位置是否符合要求，原有内容是否按要求保留；需要可读排版或可打开文件时检查实际产物。
   - 数据处理：核对口径、单位、日期、关键计算、遗漏与重复，不将缺失值擅自当作零。
   - 应用或外部操作：依据实际结果核对目标对象及状态，区分草稿、已接收、处理中、成功和失败；未知状态不重复提交。
   - 代码：沿真实入口检查本次涉及的接口、校验、状态更新、重复操作、取消和异步行为。没有仓库时直接检查文件，不为此初始化仓库。
3. 只报告有依据且可行动的问题，说明依据、位置或触发条件及影响。区分必须修正的问题与个人偏好；收到建议先核对实际成果，不盲从。
4. 本次需求中的必要问题直接修复，只补受影响的检查。无关建议不擅自实施。修复后核对相关变化，问题解决就结束，不循环组织多轮全面审查。
5. 检查结果简短说明必要问题及处理结果、仍未解决的限制。未发现问题时不声称绝对正确。随后加载「交付核对」（`dsh-focus-delivery`）；已加载则沿用。检查通过即停止，不把一般事务扩展成代码测试或多轮全面审查。
