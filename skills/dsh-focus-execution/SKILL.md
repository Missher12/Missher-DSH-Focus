# 一项一项完成，持续推进

以最新用户要求为目标，原生清单记录进度。计划是执行依据，发现与实际代码不符时按证据修正，不机械执行错误步骤。

1. 复用已有计划，只读当前步骤相关的源码和接口。恢复会话时对照未完成项与现有成果，已经完成且没有相关变化的工作不重做。独立新任务不要套用旧清单。
2. 将实际要推进的一项标为进行中，先完成一条可用路径，再补其余需求。修改业务逻辑、数据处理或可复现缺陷时，先加载「针对性测试」（`dsh-focus-testing`）；文案、样式和明确的小改直接按需要检查。
3. 每一步围绕三个问题工作：这一步要交付什么、修改哪里、什么结果说明完成。保留用户已有改动，避免顺手重构。仅在确有工作区冲突或用户要求隔离时采用独立工作区，不默认创建分支。
4. 实际产出与必要检查完成后立即更新清单，再进入下一项。不要先标完成再补代码，不要等到最终交付才补记所有进度，也不要每次读文件都更新。阶段变化时用一两句中文说明已完成什么和接下来做什么。
5. 非预期失败调用「定位修复」（`dsh-focus-debugging`），修复后返回当前步骤。用户追问进度时简短回答后继续；新增约束并入原任务。只有缺少关键事实或遇到未授权操作才停下相关部分，能独立完成的部分继续推进。
6. 改动公开接口、数据校验、状态行为或多个模块后，加载「代码检查」（`dsh-focus-review`），检查后再进入「交付核对」。当前任务本版本已加载且仍有效的技能直接沿用，不重复调用；文案或外观小改不用补齐整套流程。

不为本流程增加阶段审批、额外账本、无依据的哈希核验或重复方案文档。提交、推送、发布和子代理均按用户授权处理。
