# 按实际结果交付

1. 对照最新用户要求和当前清单，找出遗漏、阻塞和未验证项。清单“已完成”是工作记录，不是功能正确的证明。
2. 优先复用当前仍适用的验证和代码检查结果。代码、输入条件发生变化或出现具体疑点时，补最少必要的检查。没有需要比对的可信基准或明确要求时，不为收尾计算文件哈希、创建快照；也不把文件存在性当成功能完成的证明。
3. 网站和应用按本次改动检查实际交互。构建成功只能说明构建通过；本地示例、合成数据、真实服务、生产部署和日常安装是不同的验证范围，分别说明。
4. 只有实际完成的项目才标记完成。存在必要未完成项时继续解决或说明阻塞；不通过缩减需求、空壳、假数据或删除失败检查制造完成。
5. 用简短中文交代：做成了什么、如何验证、还有什么限制。给出可用的文件或运行入口，保留必要的命令、技术标识和原文，不添加装饰性英文或重复介绍技能名称。满足完成条件就结束。

提交、推送、发布、安装以及子代理使用均以用户授权为准。本技能不自动增加这些操作。
